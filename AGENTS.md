# AI Agent Instructions for MiClan

## What this repository is
- Flutter mobile app targeting Android, with Firebase backend integration: family/group location sharing, panic (S.O.S.) alerts, quick messages, group chat.
- **Read `MiClan_Informe_Tecnico_Integral_v4.md` first** — it is the authoritative, exhaustive technical reference (product goal, full data model, Firestore rules, every screen, the full GPS foreground/background architecture, notification design, and the complete bug history with root causes). This file (`AGENTS.md`) only gives quick pointers; the informe has the actual detail.
- App logic is split across `lib/services/` (business logic, Firebase access, GPS), `lib/screens/` (UI), `lib/providers/` (Riverpod), `lib/models/` (data classes) — `lib/main.dart` is bootstrap/routing/FCM handlers only, not a monolith.
- Firebase backend code lives in `functions/` and is referenced by `firebase.json`.
- Older informes (`MiClan_Informe_Tecnico_Integral_v3.md`, `INFORME_SESION_2026-08-10_GPS_Background.md`) are kept for history but are superseded by v4 where they conflict (mainly: v3's GPS section described only-foreground tracking, which is no longer accurate — see v4 section 10).

## Primary areas of focus
- `lib/services/location_service.dart` (foreground GPS) + `lib/services/background_location_service.dart` (background GPS, real Android service) + `lib/services/location_config.dart` (shared thresholds) — see informe v4 section 10 before touching any of these; there is a documented history of race-condition bugs here.
- `lib/main.dart` handles app bootstrap, GoRouter, and the FCM background/foreground handlers — keep edits targeted, it has several documented race-condition fixes (see informe v4 section 13) that are easy to accidentally revert.
- `lib/firebase_options.dart` is generated by FlutterFire and should only be updated by the FlutterFire CLI or when Firebase app config changes. Note: `lib/core/firebase_options.dart` is a stray unused duplicate — don't import it.
- `functions/index.js` is the Cloud Function that sends FCM data-only notifications.
- `firebase.json` points at `functions/` for deployment.
- `pubspec.yaml` defines dependencies like Flutter, Riverpod, GoRouter, Firebase packages, and Android-specific plugins.

## Build and deployment commands
- Install Flutter dependencies: `flutter pub get`
- Clean and refresh: `flutter clean && flutter pub get`
- Run tests: `flutter test`
- Analyze code: `flutter analyze`
- Deploy Cloud Functions from the root functions folder:
  - `cd functions`
  - `npm install`
  - `firebase deploy --only functions`

## Important repo conventions and details
- The app uses `flutter_riverpod` for state management and `go_router` for navigation.
- FCM messages are sent as data-only payloads (no `notification` field — deliberate, avoids duplicate notifications); the app relies on a local notification service to show them. See informe v4 section 11.
- Android wake/screen-on and battery optimization behavior is a key bugfix area — see informe v4 sections 10 and 13 for the documented history (including two race-condition bugs root-caused with `adb logcat` on 2026-08-10).
- Building requires JDK 17 (`android/gradle.properties` → `org.gradle.java.home`); Gradle 8.14 does not support the JBR that ships with recent Android Studio. See informe v4 section 3.2.
- There are multiple functions directories in the repo, but the authoritative backend code is the root `functions/` folder referenced by `firebase.json`.

## When editing
- Read the relevant section of `MiClan_Informe_Tecnico_Integral_v4.md` before editing GPS (`location_service.dart`, `background_location_service.dart`, `location_config.dart`) or the session/login logic in `main.dart` — both have a documented history of "looked fixed by code, wasn't" bugs that only got root-caused with real device logs.
- When modifying Firebase behavior, check `functions/index.js` and informe v4 section 11 first.
- Do not assume iOS workflows are complete; the current app is Android-only in practice.
- Keep Spanish documentation in mind; comment and variable names may use Spanish (rioplatense voseo) conventions.
- If a bug is reported as "fixed by code but nothing changed in practice", prefer getting `adb logcat` evidence from a real device over another round of code-reading hypotheses — see informe v4 section 13.8.
